# Computer Graphics Project 3 — Motion Viewer 보고서

BVH(Biovision Hierarchy) 모션 캡처 파일을 로드해 무대(stage) 위에서 골격 애니메이션을
실시간 재생하는 3D 모션 뷰어. Project 1·2 의 OpenGL 3.3 Core 뷰어(카메라·셰이더·OBJ 로더·
Node 트리)를 확장해 구현했다. 허용 모듈(NumPy, PyOpenGL, glfw, PyGLM, Pillow)만 사용하며
`python main.py` 로 실행한다.

## 2. Core Motion Viewer

### A. 골격 모션의 시각화 방식과 그 표현을 선택한 이유

**(1) BVH → Joint 트리 + 전방 운동학(FK)**
BVH 의 `HIERARCHY` 섹션을 스택 기반으로 파싱해, 부모→자식으로 글로벌 변환을 누적하는
Joint 트리를 만든다. 이 트리는 Project 2 의 `Node` (계층 변환 누적 트리)와 동형이며,
P2 의 `update_tree_global_transform` 패턴을 그대로 재사용한다. 각 joint 의 글로벌 변환은

```
local  = T(offset) · R(local_rotation)          (루트는 T(root_pos) · R)
global = parent.global · local                  (FK)
```

로 계산한다. 회전 채널 순서(rotation order)는 joint 마다 다를 수 있으므로(이 데이터셋은
루트가 `Xpos Ypos Zpos` + `Zrot·Yrot·Xrot`(ZYX), 그 외 joint 는 `Zrot·Xrot·Yrot`(ZXY))
**파일에 적힌 순서 그대로** 곱하고, 각도는 degree→radian 으로 변환한다. 이 "채널 순서 준수"가
BVH 재생의 가장 흔한 버그 지점이다.

**(2) 중립 표현 `Pose` 로의 변환**
각 프레임을 raw 채널 배열로 두지 않고 **중립 표현 `Pose`(루트 위치 `vec3` + joint 별 로컬
회전 `quaternion` 리스트)** 로 미리 변환한다. 이렇게 하면 렌더·클립 정렬·전환 보간이 모두
동일한 형식으로 처리되고, 회전을 쿼터니언으로 다루므로 짐벌락과 오일러 wrap 문제가 없다.

**(3) 골격 렌더링 — 뼈를 직육면체(box)로**
- **뼈(bone)**: 부모 joint → 자식 joint 를 잇는 선분을 **단위 박스(직육면체)** 로 표현한다.
  단위 박스(밑면 원점, +Y 로 길이 1)를 `translate(p0)·R(+Y→방향)·scale(두께, 길이, 두께)`
  로 배치한다(`bone_matrix`). 단위 박스 VAO 하나를 만들어 모든 뼈가 재사용한다.
- **무대(stage)**: `stage.obj` 를 `obj_loader` 로 로드해 단일 VAO·`Node` 로 깔고, 골격이 그 위에
  서도록 배치한다.

**표현을 이렇게 선택한 이유**
- **뼈를 선(line)이 아닌 직육면체로 그린 이유**: 실제 부피를 가지므로 Phong 음영으로 깊이·
  방향감이 살아 골격의 3D 자세가 선보다 훨씬 잘 읽힌다. 또 무대와 **같은 Phong 머티리얼
  경로**를 공유해 한 장면에서 일관된 음영을 얻고, position+normal 인터리브 레이아웃이
  `obj_loader.make_vao` 와 동일해 P2 코드를 그대로 재사용할 수 있다.
- **Pose(쿼터니언) 추상화를 둔 이유**: 동일 골격 클립끼리 1:1 로 대응되는 회전을 안정적으로
  보간(전환)하려면 쿼터니언이 필요하고, 렌더/정렬/보간을 한 형식으로 통일하면 코드가 단순
  해진다.
- **자동 스케일 + 지면 정렬**: BVH 마다 단위가 달라 골격 크기가 제각각이므로, rest pose 의
  bounding-box 높이를 목표 키에 맞추는 스케일을 자동 산출한다. 시퀀스의 모든 클립이 같은
  골격이라 **단일 스케일**을 공유하므로 전환 시 크기 점프가 없다. 또 전 프레임에서 발(말단
  joint)의 최저 월드 Y 를 구해 그 값이 무대 윗면(y=0)에 오도록 수직 오프셋을 더해, 골격이
  무대를 뚫거나 공중에 뜨지 않게 했다.

### B. 인터랙션 설계와 그렇게 설계한 이유

**카메라 조작 (Project 1·2 재활용)**
- 좌클릭 드래그: orbit(방위각·고도각 회전). 뒤집힘 방지를 위해 고도각을 ±90° 직전으로 클램프.
- 우클릭 드래그: pan(시점 평행 이동).
- 마우스 휠: zoom(중심점까지 거리 조절, 최소 거리 제한).

**재생 제어 (신규)**
| 키 | 동작 |
|---|---|
| `Space` | 재생 / 일시정지 토글 |
| `←` / `→` | 한 프레임 뒤로 / 앞으로 (스크럽, 누르면 자동 일시정지) |
| `[` / `]` | 재생 속도 감소 / 증가 (0.25× ~ 4.0×, 0.25 단계) |
| `R` | 처음으로 리셋 후 재생 |
| `Esc` | 종료 |

**그렇게 설계한 이유**
- **시간 기반 재생**: 매 프레임 `dt × 속도 / frame_time` 만큼 진행시켜, 화면 주사율과 무관하게
  BVH 의 실제 frame time(여기서는 120fps)에 맞는 속도로 재생된다(요구사항: frame time 에 따른
  실시간 재생). `% num_frames` 로 자동 루프.
- **스크럽이 일시정지를 동반**하는 이유: `←/→` 로 전환 경계 프레임을 한 칸씩 멈춰 세워 자세
  연속성을 눈으로 검증하기 위함이다.
- **속도 조절**을 넣은 이유: 0.25× 로 느리게 돌리면 walk↔dance 전환이 매끄럽게 이어지는지
  세밀하게 확인할 수 있다(시연·디버깅 모두에 유용).
- **카메라는 P1/P2 와 동일한 조작**을 유지해 학습 비용 없이 익숙하게 쓰도록 했고, 재생 제어
  키만 새로 추가해 두 관심사를 분리했다(`input.py` 의 전역 상태를 main 루프가 읽어 재생).

### C. 사용한 BVH 파일 — 출처 데이터셋과 모션 설명

> **출처 데이터셋:** **motion.hahasoha.net** (http://motion.hahasoha.net/) — 공개 모션 캡처
> BVH 라이브러리. 제공되는 골격은 Poser/DAZ 계열 인물 리그(Biovision/Poser-style)이다.

골격은 **`hip` 을 루트로 하는 43개 관절**(+ End Site 14개)로 이루어진 Poser/DAZ 스타일
리그다. 척추 계열
(abdomen·chest), 목·머리와 눈(neck·head·leftEye·rightEye), 양쪽 어깨 사슬(rCollar·rShldr·
rForeArm·rHand)과 손가락 마디(rThumb·rIndex·rMid·rRing·rPinky 1·2), 양쪽 다리(rButtock·
rThigh·rShin·rFoot)를 포함한다. 채널 순서는 루트가 `Xpos Ypos Zpos Zrot Yrot Xrot`,
나머지 joint 는 `Zrot Xrot Yrot` 이며 frame time 은 0.00833333초(**120 fps**)다.

| 파일 | 프레임 수 (≈길이) | 모션 |
|---|---|---|
| `walk_stop.bvh` | 348 (≈2.90s) | 걸어 들어와 멈추는 보행(walk) — 시퀀스의 첫 클립 |
| `dance2.bvh` | 1096 (≈9.13s) | 춤(dance) |
| `walk.bvh` | 299 (≈2.49s) | 보행(walk) — 시퀀스의 마지막 클립 |

세 클립은 **HIERARCHY·OFFSET·채널·frame time 이 완전히 동일한 같은 골격**이다. 따라서 한 개의
Joint 트리를 공유하고 프레임만 바꿔 끼울 수 있으며, joint 끼리 1:1 로 대응되므로 **포즈 블렌딩
(전환 보간)이 성립**한다 — 이것이 §3 모션 응용의 전제 조건이다.

## 3. Motion Application / Exploration

### A. 탐구한 모션 아이디어 / 응용

**여러 모션의 블렌딩 / 전환(Motion blending / transition between motions)** 을 구현했다.
구체적으로는 `walk_stop → dance → walk` 세 클립을 **하나의 연속된 타임라인**으로 이어
"무대 위로 걸어 들어와 → 춤추고 → 다시 걸어 나가는" 하나의 퍼포먼스로 재생한다.
이때 두 가지 인공물(artifact)을 제거하는 것이 핵심 목표였다.
1. **위치 순간이동(teleport)** — 다음 클립이 이전 클립이 끝난 자리·방향에서 이어지도록 정렬.
2. **자세 급변(pose pop)** — 동작 경계에 짧은 전환 구간을 끼워 모든 관절 회전을 부드럽게 보간.

### B. 그 아이디어를 선택한 이유 / 흥미로웠던 점

모션 캡처 데이터셋은 보통 **서로 독립적으로 촬영된 개별 클립**으로 제공된다. 이를 그대로
이어 붙이면 클립 경계에서 캐릭터가 순간이동하거나 자세가 툭 끊긴다. "걸어 들어와 춤추고
걸어 나간다"는 자연스러운 한 편의 동작을 만들려면, **별개로 캡처된 클립들을 같은 골격 위에서
공간적(위치·방향)·시간적(자세)으로 매끄럽게 봉합**해야 한다. 이 봉합 문제 자체가 게임·애니
메이션의 모션 그래프/블렌딩의 핵심이라 가장 흥미로웠다. 특히
- 쿼터니언 보간으로 짐벌락 없이 자세를 잇는 부분,
- BVH 클립 앞뒤에 흔히 들어있는 **T자 캘리브레이션 자세와 그 직후의 급가속 구간**이 전환을
  망치는 현상을 발견하고 이를 잘라내 해결한 부분
이 단순한 재생을 넘어선 실제 모션 처리의 맛을 보여주었다.

### C. 동작 방식과 결과 (구현 방법)

전환은 `motion_sequence.py` 에서 네 단계로 만든다. 같은 클립이 여러 번(walk가 처음·끝) 쓰이
므로 원본 Pose 를 변형하지 않고 **복사본**에 적용한다.

**⓪ 트리밍 (T자/스냅 램프 제거)** — BVH 클립은 보통 frame 0 의 T자(rest) 자세에서 몇 프레임에
걸쳐 본 동작으로 급가속한다. 이 고속 램프가 남으면 전환 직후 "움찔"거린다. 그래서 클립의
선행/후행에서 **자세 활성도가 낮거나(rest) 각속도가 중앙값의 일정 배를 넘는** 프레임을 함께
잘라내, 전환이 "다음 동작의 실제 시작 자세"로 향하게 한다.

**① 위치·방향(yaw) 정렬 (순간이동 제거)** — 다음 클립 전체를 Y축으로 회전시켜 진행방향(heading
yaw)을 이전 클립 끝의 방향에 맞추고, 회전 후 시작점의 XZ 를 이전 클립 끝 위치에 일치시킨다.
수직 Y 와 잔여 자세 차이는 ②의 전환 구간이 흡수한다. 루트만 변환하므로 클립 내부의 걸음·춤
동작은 그대로 보존된다. 또 **마지막 walk 는 처음 walk 와 같은 방향**으로 정렬해, 들어온 방향
으로 자연스럽게 되돌아 나가도록 했다.

**② 전환 보간 (자세 급변 제거)** — 정렬된 두 클립 사이에 `T = 60` 프레임(120fps 기준 0.5초)을
새로 생성해 끼운다. 모든 자유도(DOF)를 `t` 를 0→1 로 선형 증가시키며 블렌드한다.
- 루트 위치: 성분 선형보간(lerp) `A = B(1−t) + C·t`
- 모든 joint 회전: **쿼터니언 구면 선형보간(slerp)** — `dot < 0` 이면 부호를 반전해
  최단경로로 회전(짐벌락·오일러 wrap 없음).

이징(smoothstep) 대신 등속 선형보간을 쓴 이유는, 이징을 쓰면 전환 양끝에서 속도가 0이 되며
오히려 "멈칫" 끊김이 생기기 때문이다.

**③ 통합 타임라인** — `clip0 + trans + dance + trans + walk` 를 단일 `poses` 리스트로 합치고,
세그먼트 경계(walk/dance/transition)를 라벨로 기록해 디버깅·검증에 쓴다. main 루프는 이
타임라인을 시간 기반으로 재생하며 끝에서 처음으로 자동 루프한다.

**결과** — 클립 경계의 XZ 위치 점프가 0에 수렴하고(순간이동 제거), 전환 구간에서 자세가 툭
끊기지 않아 walk→dance→walk 가 하나의 연속 동작처럼 재생된다. 골격은 무대 위에서 들어온
방향으로 다시 걸어 나가며 매끄럽게 반복된다.
